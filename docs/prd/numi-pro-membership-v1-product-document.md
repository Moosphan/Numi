# Numi Pro 会员产品文档（V1.0）

> 状态：可作为产品、设计、iOS 与测试的共同基线
>
> 更新时间：2026-09-06
>
> 适用范围：iOS 首次正式商业化；月付、年付、终身买断；本地优先记账产品

## 0. 结论先行

Numi 的 Pro 不应出售“能不能记一笔账”，而应出售三种增量价值：

1. **规模**：从个人轻量记账，扩展到多账本、多账户、多币种与更多计划；
2. **省心**：自动汇率、订阅和分期提醒、到期记账、后续 AI 与自动化；
3. **保障与洞察**：加密备份、经验证的跨设备同步、高级预算和高级洞悉。

免费版必须保留完整且可长期使用的单人本地记账闭环：不限记录、收支转账、基础账户/分类、搜索编辑删除、基础预算和洞悉、手动导入导出、隐私锁与本地保存。收费只发生在用户主动追求更多规模、自动化、跨设备保障或深度分析时。

**V1 商业化决策：**

- 上线商品：`月付`、`年付（默认推荐）`、`终身买断`，三者权限一致，仅有效期不同；
- 当前可实际售卖的 Pro 权益仅包含已实现且已接入统一 Feature Gate 的能力；
- iCloud 同步、AI、增强 Siri、批量处理、高级洞悉/预算、主题和高级导入导出，虽已建能力枚举或已有部分代码，但在满足各自发布门槛前不得写成“已解锁权益”；
- 终身版不承诺未来产生持续外部成本的 AI 无限调用。若未来接入 OCR/多模态或付费模型，采用“Pro 可用 + 公平额度/自带 API Key”而不是事后收回终身权益。

## 1. 产品背景、目标用户与边界

### 1.1 产品定位

Numi 是一款 iOS 本地优先的记账 App。用户数据默认保存在设备；导入、导出与备份可由用户掌控；云同步是可选能力，而不是强制账号体系。Pro 的定位是“让用户把已经建立的记账习惯扩展成更完整的钱包系统”，不是以广告、数据交易或阻断基础能力变现。

### 1.2 目标用户与付费动机

| 用户 | 核心任务 | 免费版应满足 | 触发 Pro 的自然时刻 |
| --- | --- | --- | --- |
| 轻量个人用户 | 每日记录收支、回看本月 | 无限记录、分类、账户、基础预算/洞悉 | 通常无需付费 |
| 多场景个人用户 | 区分生活/旅行/副业，管理多张卡和多种货币 | 前两个账本、前 20 个账户、手动汇率 | 创建第 3 个账本、启用自动汇率或跨币种汇总 |
| 有固定账单/债务的用户 | 管理订阅、分期、还款日 | 少量订阅和分期、基础提醒 | 新建第 4 个订阅或第 3 个分期，需要长期自动化 |
| 重视数据安全的用户 | 换机、恢复、跨设备使用 | 本地数据、JSON/CSV 导出、导入前恢复 | 创建加密备份、等待已验证的 iCloud 同步 |
| 效率型用户 | 减少录入和整理时间 | 手动/快捷记账 | AI 识别、批量编辑、增强快捷指令正式可用后 |

### 1.3 非目标与不可收费底线

- 不通过广告、售卖财务数据或强制账号来补贴免费版；
- 不锁定历史数据、导出、删除、编辑、恢复或取消订阅；
- 不把 Face ID/密码锁、后台模糊、隐藏金额等私密性保护作为付费门槛；
- 不在首笔记账、导入失败、恢复数据或用户遇到错误时弹出升级广告；
- 不在功能仅有“Partial”实现时用营销承诺制造付费预期。

### 2.2 竞品共性与 Numi 的取舍

| 模式 | 证据 | Numi 决策 |
| --- | --- | --- |
| 按月、按年、终身并列 | Cookie 明确提供三种内购 | 采纳。年付默认选中；月付保留给低承诺用户；终身版作为一次性长期数据层权益。 |
| 用自动化、同步、规模制造付费价值 | Cookie 的 AI/多账本/汇率/iCloud，MoneyWiz 的同步/银行同步 | 采纳。Numi 的首批价值为无限结构、自动汇率、加密备份与高级计划额度。 |
| 以“成果”表达价值 | YNAB 把目标、清晰度、协作和同步组织为一个结果包 | 采纳。Numi 的 CTA 表述“把记账系统补完整”，而非“购买 15 项功能”。 |
| 基础操作也强绑定订阅 | YNAB 是全订阅产品 | 不采纳。Numi 的本地优先承诺要求保留可长期使用的免费基础闭环。 |
| 多层订阅 | MoneyWiz Standard/Premium | 暂不采纳。Numi 现阶段功能成熟度和用户量不足以支撑多个权益层；先把一个 Pro 层做可信。 |

## 3. Numi 当前功能证据审计与会员归类

### 3.1 判定口径

- **永久免费（F）**：核心记账、可迁移性、隐私保护或质量基础设施；绝不因订阅状态受阻。
- **Pro 已可售（P0）**：能力已实现、用户入口已接入统一 `MembershipFeatureGate`，且免费受限时不伤害历史数据。
- **Pro 候选，暂不售卖（P1）**：有代码、模型或能力枚举，但尚缺端到端验收、真实服务能力或 UI gate；只能在路线图出现，不得在权益页标为已解锁。
- **未来能力（P2）**：尚未实现；不应出现在购买承诺中。
- **非产品权益（N）**：工程/设计系统/质量项，不对用户收费。

### 3.3 当前 Gate 与产品承诺的差异

现有领域模型已定义 14 类 `MembershipCapability`，且统一的 `MembershipFeatureGate` 已覆盖账本、账户、订阅、分期、自动汇率、iCloud 启用和加密备份创建。这个架构是正确的，但**能力枚举不等于可以营销**。

当前权益页必须只把以下内容标为“现可用”：无限账本、无限账户、无限订阅、无限分期、加密备份。自动汇率、多币种和 iCloud 仅在各自端到端验收通过后改为“现可用”。AI、高级洞悉/预算、批量处理、主题、增强 Siri、高级导入导出必须标为“规划中”或从权益对比中移除，直至真正交付。

| 隐私锁/隐藏金额/后台模糊 | 有 | 有 | 有 | 隐私保护，始终免费 |
| 多币种、自动汇率、iCloud | 未在 V1 对外销售 | **发布核验后才加入** | **发布核验后才加入** | 不在未验证状态承诺 |
| AI、高级洞悉/预算、批量、主题、增强 Siri | 未提供/基础免费 | 后续版本按实际交付新增 | 后续版本按实际交付新增，AI 可能有额度 | 不提前卖未来功能 |

## 5. 体验规格：从入口到购买后的长期状态

### 5.1 升级入口与频率规则

| 场景 | 触发条件 | 页面/文案重点 | 禁止行为 |
| --- | --- | --- | --- |
| 设置页入口 | 用户主动点击 Numi Pro 状态卡 | 展示完整套餐和权益对比 | 首次启动或首次记账自动弹出 |
| 账本上限 | 点击创建第 3 个账本 | “免费版可使用 2 个账本；升级后可无限创建” | 隐藏已有账本、阻断切换 |
| 账户上限 | 点击创建第 21 个账户 | 说明无限账户及多场景管理 | 锁定/删除第 21 个以前账户 |
| 订阅/分期上限 | 创建第 4 个订阅/第 3 个分期 | 对应当前任务的收益与年付默认方案 | 使用泛化的“所有功能都在 Pro”空洞话术 |
| 加密备份 | 主动点击创建加密备份 | 强调加密保护；普通导出仍可用 | 将恢复已有备份也设为付费 |
| 后续高级能力 | 用户主动点击已上线功能 | 只展示与该能力相关的 2–3 个收益 | 在失败、数据丢失或导入错误时插入 paywall |

同一个被拒绝场景在 24 小时内只出现一次全屏权益页；用户取消后回到原页面并保留表单已填写内容。所有拒绝分支均通过 `MembershipFeatureGate.decision(for:)` 返回 `blocked(context:)`，页面不得直接判断商品 ID 或会员计划。

### 5.2 会员页信息架构

1. 导航标题与简短承诺：`解锁 Numi Pro` / `更完整地管理你的钱`；
2. 4–5 张横向权益卡，只展示**实际已上线或有明确发布日期**的价值；
3. 月/年/终身三张紧凑方案卡，年付默认选中；
4. 完整免费/Pro 对比表，准确显示“2 个”“20 个”“不限”等限制；
5. 底部固定购买 Dock：主 CTA、自动续订说明、用户协议、隐私政策、恢复购买；
6. 已购用户显示当前方案、到期日期（订阅）、管理订阅入口和恢复结果，不再显示误导性“再次订阅”。

视觉规则沿用当前 `NumiColor`、`NumiFont`、`NumiSpacing`、`NumiRadius`。使用浅色、低饱和插画承载场景；方案卡高度以内容为准，避免价格加载前后跳动；底部 Dock 有轻阴影与实体背景，在可滚动对比表上始终可见。四种运行时语言 `zh-Hans`、`zh-Hant`、`en`、`ja` 必须在同一次 PR 中完成。

### 5.3 购买、恢复与状态机

| 状态 | 页面行为 | 结果与用户反馈 |
| --- | --- | --- |
| 加载商品 | 方案价格位置显示骨架/占位，CTA 禁用 | 可重试；不得显示硬编码价格 |
| 商品可用 | 显示 `Product.displayPrice`，CTA 可点击 | 年付默认；月/终身可切换 |
| 购买中 | CTA loading 且防重入 | 保留选中方案 |
| 已购买且验证通过 | 刷新 `MembershipStatus`，立即放行能力 | 成功提示 + 回到触发任务或显示会员状态 |
| 待批准 | 显示“等待购买批准”，不误称失败 | 后台/前台交易更新后自动刷新 |
| 用户取消 | 不弹错误，不改变权限 | 保留当前页与选中方案 |
| 验签/购买失败 | 显示可理解错误和重试 | 不解锁，不写假缓存 |
| 恢复购买 | 调用 App Store sync 并刷新 entitlement | 已恢复/无可恢复/失败三种明确反馈 |
| 订阅到期/退款/撤销 | 交易更新与前台刷新重新计算权益 | 停止新建超额实体；历史数据及基础操作继续可用 |

### 5.4 降级与数据保护规则

- 降级永远只限制“新建超额项目”或“开启高级自动化”，不删除、隐藏、只读化已有账本/账户/订阅/分期；
- 允许继续完成既有分期的还款、跳过、提前结清与到期日调整；
- 普通 JSON/CSV 导出、导入恢复点和已有加密备份恢复始终可用；
- 缓存会员态只能用于短时展示，不能在未验证 StoreKit entitlement 时解锁能力；
- 购买流程不依赖 Numi 账号；用户通过 Apple ID 的 StoreKit 购买与恢复操作管理权益。

## 6. 后续 Pro 能力的准入标准

新权益不能只因为“看起来高级”就进入付费墙；需同时满足以下 6 条：

1. 用户能用一句话理解节省了什么时间、降低了什么风险或扩展了什么规模；
2. 免费主路径在没有该能力时依然完整；
3. 数据模型、异常/撤销路径和多语言文案都已完成；
4. 入口统一经过 `MembershipFeatureGate`，且有免费、Pro、降级三类测试；
5. 若依赖网络、云或模型调用，具有明确的隐私说明、成本上限、失败恢复和服务可用性策略；
6. 在权益页、商店元数据与实际行为中可被一致证明。

### 6.1 后续候选的设计结论

| 候选 | 建议层级 | 上线前必备条件 |
| --- | --- | --- |
| 多币种/自动汇率 | Pro | 汇率日期快照、跨币种统计、导入导出及离线/失败状态端到端验证；不影响已有手工汇率数据。 |
| iCloud 同步 | Pro | 真机两设备、冲突合并、离线恢复、删除传播、容量/隐私披露验收；未通过前隐藏而非半成品收费。 |
| 高级预算/洞悉 | Pro | 分类/账户预算、报销退款规则、任意时间范围、高级报告都具备准确测试；基础预算/趋势继续免费。 |
| AI 录入 | Pro 或 BYO-Key 增强 | 明示传给哪家模型、保留多久、能否关闭；加入校正草稿、限额、超额策略。终身版不得承诺无限平台成本。 |
| 增强 Siri/批量编辑 | Pro | Shortcut 真实端到端测试；批量修改预览、撤销与权限检查。 |
| 高级导入导出 | Pro | 仅可收费“保存映射模板/高级报表”等增量效率；基础 CSV/JSON 与恢复能力保持免费。 |
| 主题/App Icon | Pro 低优先级 | 默认主题、深浅色、字体缩放与四语言永远免费；不能成为首屏核心卖点。 |

## 7. 指标、隐私与发布验收

### 7.1 最小埋点（不采集金额、商户、备注或交易正文）

| 事件 | 属性 | 用途 |
| --- | --- | --- |
| `paywall_opened` | `context`, `tier`, `language` | 找到有价值的升级时刻 |
| `plan_selected` | `plan`, `context` | 评估套餐理解与年付偏好 |
| `purchase_started/completed/cancelled/failed` | `plan`, `failure_category` | 漏斗与支付问题排查 |
| `restore_result` | `result_category` | 恢复购买可靠性 |
| `feature_gate_blocked` | `request`, `current_count` | 检验额度是否合理 |
| `membership_status_refreshed` | `source`, `tier` | StoreKit 更新和缓存展示健康度 |

只记录匿名产品事件与枚举状态；不上传交易金额、分类、账户名称、原始 AI 输入或 Apple ID。

### 7.2 V1 上架 Definition of Done

- [ ] App Store Connect 建立与代码一致的三件商品，并在至少一个 Sandbox Apple ID 完成购买、取消、待批准、恢复、续订/到期和退款验证；
- [ ] 填入正式 `NumiTermsURL` 与 `NumiPrivacyURL`，页面链接可访问且与 App Store 资料一致；
- [ ] 每种商品价格均来自 StoreKit，区域切换不展示测试价格或硬编码币种；
- [ ] 免费/Pro/到期后三组自动化测试覆盖：账本、账户、订阅、分期、加密备份以及基础导出不受影响；
- [ ] iCloud、多币种、AI 等未完成权益不出现在“已解锁”承诺中；
- [ ] 所有新增或修改文案覆盖 `zh-Hans`、`zh-Hant`、`en`、`ja`，并完成动态字体、VoiceOver、深浅色和小屏检查；
- [ ] 隐私、退款、自动续订、恢复购买和终身版 AI 例外均通过产品与法务复核；
- [ ] 埋点遵守“无财务内容上传”边界，且可被用户隐私说明覆盖。

## 8. 分阶段交付路线

| 阶段 | 目标 | 必须交付 | 不做 |
| --- | --- | --- | --- |
| V1.0：可信收费闭环 | 用实际可用能力完成首发 | StoreKit 真商品、状态刷新/恢复、账本/账户/订阅/分期额度、加密备份、真实法律链接、四语言 | 不销售未验证 iCloud、AI、高级洞悉 |
| V1.1：多币种与云保障 | 扩大高价值付费理由 | 汇率端到端、多设备同步验证、冲突与恢复策略 | 家庭共享、银行连接 |
| V1.2：高级财务管理 | 深化留存与年付价值 | 分类/账户预算、报销退款规则、高级洞悉、专项报表 | 用基础预算强迫升级 |
| V1.3：效率与智能 | 以可控成本提升录入效率 | AI 草稿/校正/额度、增强 Siri、批量编辑 | 无限外部 AI 承诺 |

每一阶段发布前重新执行第 6 节准入标准。权益新增是产品版本决策，不是仅在 `MembershipCapability` 枚举中加一个 case。
